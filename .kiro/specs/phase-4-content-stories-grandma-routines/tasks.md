# Implementation Plan: Phase 4 Content, Stories, Grandma, Routines

## Overview

Build order: the shared foundations every wave needs (the content model, the Activity and report types, the five log kinds, the Starter_Content folder); then the seven feature waves in order — content library, storyteller and branching stories, Grandma, routines and limits, reports, the Admin_Console Content tab, the parent app's four screens; then the Repo_Checks, Compose and docs, and a final verification with the Done-when report.

Every wave is built behind a store interface with an in-memory implementation. The interface comes first, the implementation second, and every caller depends only on the interface, because Phase 5 swaps in a Supabase implementation and there must be no rework.

TypeScript strict throughout. Kebab-case files, PascalCase types, snake_case wire and log fields. **No new dependency in any manifest.** No `fetch` in the gateway, no network import under `brain/`, no transport folder added, no file-writing API, no byte-typed value outside the existing `AUDIO_BYTE_MODULES`. No non-loopback URL literal and no Panel_Key assignment line in tracked source. `.env.example` and `tooling/fixtures/approved-panel.txt` are not touched and the panel key count stays 23. No Document B change: if one looks necessary, stop and record it under F6. No git commits until the final task.

Toolchain for every command (PowerShell): `$env:Path = "c:\xelulu\.tools\node-v24.21.0-win-x64;" + $env:Path; $env:COREPACK_HOME = "c:\xelulu\.tools\corepack"; $env:COREPACK_ENABLE_DOWNLOAD_PROMPT = "0";` then `corepack pnpm ...` with cwd `c:\xelulu`. Never system Node 22 or a global pnpm. Redirect noisy output to a log under `c:\xelulu\.tools\` and delete it afterwards.

Green baseline that must not regress, measured on this tree: `corepack pnpm test` = 103 Vitest files / 2,116 tests plus 13 parent-app Jest suites / 267 tests; `corepack pnpm lint` and `corepack pnpm format:check` clean. This phase deletes no test file, so nothing may move down.
